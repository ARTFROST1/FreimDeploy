Freim Deploy & FreimSite

One is a self-hosted deploy platform. The other is the site template built for it. This page explains both and links to everything either one has written down.

What Freim Deploy is

Freim Deploy is a self-hosted deploy platform, built to feel like Vercel or Netlify while the server, the domains and the data stay yours. Put it on a VDS you already pay for, and it takes over the parts of shipping a site that are normally someone else's SaaS: it watches a Git repository, builds it, issues and renews HTTPS certificates, and keeps a history of releases you can roll back to in about a second.

It runs on Node 22, SQLite, Caddy and systemd, with no Docker, no Kubernetes and no vendor account watching what you deploy. One panel can manage several servers and an unlimited number of projects, which is what makes it a reasonable base for a freelancer or a studio hosting more than one client.

Framework autodetection covers Next.js, Astro, Nuxt, SvelteKit, Remix, Python and plain static output. Deploys can trigger from a click in the dashboard, the CLI, or a Git push once a webhook is connected, for repositories on GitHub, GitLab, Gitea or Bitbucket.

What FreimSite is

FreimSite is the official site template for Freim Deploy: an Astro 7 starter, not a page builder. It ships SEO groundwork, islands architecture, zero JavaScript by default, and about twenty content collections defined with Zod schemas, so the shape of a page's content is validated at build time rather than guessed at.

What sets it apart from a generic starter is markup, not tooling. Every block a client might reasonably want to change carries a small data attribute contract, read and written by a separate web app: the CMS portal. Nothing about that contract requires the client to open a code editor.

It is MIT licensed and marked as a GitHub template repository, so starting a new site from it is a button, not a fork-and-rename.

How they connect

Neither product does much alone. FreimSite is a repository until something builds and serves it, and Freim Deploy is a build-and-serve engine until it has something worth deploying. Together, one path runs from a GitHub repository to a client editing their own site:

  1. RepositoryStart a site from FreimSite, or point the platform at any repo it can build.
  2. PanelFreim Deploy pulls it, detects the framework, and builds it.
  3. Live site, its own domainHTTPS is issued automatically; the release goes live once its healthcheck passes.
  4. The client edits it themselvesThey open the CMS portal, click a heading or a price on the live page, and type.
  5. Committed and redeployedThe edit becomes a Git commit, and the platform ships it. No code editor, ever, for the client.
